# Worker cache v2 contract (draft candidate, separate from append-only v1)

This is a bounded derived presentation cache, not audit history or a persistent AI runtime. SQL ingestion stays private to the existing owner/management writer; no client write grants, credentials or schedules are added. The existing public status ROW has a separate nullable JSONB column `team_work` carrying the snapshot. The financial `payload` JSON remains unchanged. Fetch id,payload,team_work from the same existing public status endpoint and validate them independently. Before this column is installed, only an exact missing-column/schema-cache response may fall back to the existing id,payload read with the coding feed disconnected. Retry the column-aware read on later polls; never treat authentication/network failures as an absent column. Reject any conflicting legacy payload.team_work field rather than silently preferring it. Missing/invalid v2 means disconnected. Do not feed v2 into the v1 history validator.

## Public snapshot

- `version: 2`, `bridge_version: "team-work-cache-v2"`, `origin: "assistant_observed"`
- `snapshot_revision`: monotonic positive/zero integer across session takeovers; only accepted new evidence increments it. Fixed evidence has identical bytes; reads and general market writes do not renew any timestamps.
- `content_at`: last accepted publisher/worker receipt timestamp, ISO UTC milliseconds, or null before any session. This is content time, not polling/response time.
- `session_id`: UUID or null; `session_generation`: permanent monotonic server-issued integer (0 absent); `session_revision`: publisher-stream revision (0 at open); `session_state`: absent/open/closed.
- `publisher_observed_at`, `publisher_received_at`: ISO UTC milliseconds or null.
- `history_complete: false` always.
- `limits`: exactly `worker_fresh_ms:60000`, `publisher_fresh_ms:60000`, `worker_display_ms:21600000`, `recent_display_ms:3600000`, `worker_slots:6`, `recent_slots:8`.
- `workers`: at most six full CURRENT worker envelopes, in slot order.
- `events`: at most eight recent real transitions in event_number order. Heartbeat/status_observed renewals are omitted. Oldest events are omitted to target a6KiB transport snapshot; all current workers take priority and may exceed this target, subject to the16KiB hard cap. Display only events received in the last hour. Explicitly incomplete recent activity; never infer missing transitions, lifecycle success or proof completeness.

Each worker item has all 17 existing v1 envelope fields (id/session_id/session_seq/kind/observed_at/actor_id/role/run_id/run_seq/state/task/step/source/candidate_sha256/result/handoff_from_run_id), plus `slot` 1..6, `session_generation`, `run_generation`, `revision`, `received_at`, `payload_sha256`.

Worker `session_seq` is always 0 in v2 (publisher CAS is separate). Worker `run_seq` equals `revision`; 0 means task_started, later accepted updates strictly increase. Generations/revisions are not restricted to 127. Source/result narrow fields and digest correspondence retain the v1 schema; a digest is content identity, not a signature or proof execution happened. Source and candidate must be supplied in full, with no implicit inheritance.

Each recent item has the same envelope plus `event_number`, `session_generation`, `run_generation` (null for session events), `slot` (null for session events), `received_at`, `payload_sha256`. Its retained worker revision is envelope run_seq. Event numbers are global monotonic across sessions and ring overwrite, not contiguous history proof.

## Client truth/ordering

Client receives an authoritative current-state snapshot rather than replaying history. Reject malformed values, unknown contract versions, duplicate slots/actor/run identities, wrong envelope/session correspondences, receipt before observation, future timestamps, source/result contradictions or structurally inconsistent state. Compare generation/revision across observed snapshots; never replace newer known snapshot_revision/session_generation with an older one. A session-generation change resets per-session display state. A slot's run_generation must never decrease even when its run disappears. Retain only bounded six-slot fences, not unbounded event/run IDs. A changed payload at the exact same snapshot revision is conflicting evidence and must fail closed.

A current worker is live only when session_state=open AND publisher observation and receipt are both <=now and no older than60s AND this worker's observation and receipt are both <=now and no older than60s AND its state=running. blocked is observed blocked, not actively running. completed/failed are historical terminal results, never live. Six worker leases expire independently. Publisher heartbeat does not renew worker freshness. Hide worker payload older than6h while keeping client ordering fences. Derive all age at read/render time, never from market status updated_at or a poll time. On clock rollback/future evidence fail closed; a resumed tab requires fresh current producer evidence before showing live. No synthetic typing or code-execution claims.

## Private SQL API

`publisher_update(p, expected_generation, expected_revision)` accepts session_opened (session_seq0; expected current generation and expected_revision0), publisher_heartbeat/session_closed (current generation and revision, envelope session_seq=revision+1). Returns duplicate,generation,revision. New session requires absent/closed/expired predecessor; generation increments and fences prior producers. Last exact operation retry acknowledges without writes/time renewal; older retries reject.

`worker_update(slot,p,expected_session_generation,expected_run_generation,expected_revision)` accepts task_started (run_seq0; expected prior slot run generation and expected_revision0), otherwise current run generation/revision with envelope run_seq=revision+1. Returns duplicate,session_generation,run_generation,revision. New run requires never-used slot, terminal predecessor, expired predecessor or new publisher generation. A genuinely newer fresh observation may resume the same nonterminal run after display lease expiry; duplicate/stale evidence cannot. Terminal runs can never resume. Require genuinely fresh observation; no heartbeat manufacture. Last exact retry acknowledges without writes/time renewal; older retries reject. Actor/run uniqueness is scoped to retained current session slots; generation fencing, not everlasting UUID storage, prevents replay.

`publish()` coalesces accepted changes into one precomputed projection + status write. Returns changed/revision. Repeated publish at fixed evidence performs no row writes. Ingestion never locks economic/control rows; publication locks publisher then existing status (same order even when ingestion and publish share a transaction). All locks use250ms timeout. Physical/real PostgreSQL contention is not proven by local PGlite tests.

There is no cache trigger on market status writes. publish updates only the separate team_work column and preserves payload, research_v1 and updated_at exactly. The existing research BEFORE UPDATE OF payload trigger is untouched and does not run on cache-only publication. Ordinary engine writes do not invoke any cache function. The existing three-value positional INSERT/UPSERT form remains valid; omitted trailing team_work defaults to NULL on a new row and stays unchanged on the existing payload/updated_at conflict-update path. New cache tables and the new column use existing storage/autovacuum defaults.
